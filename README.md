# Mini NPU MAC 시뮬레이터

## 실행 방법

Python 3.8 이상에서 외부 라이브러리 없이 실행한다.

```text
python main.py
```

`1`을 선택하면 3×3 필터 A/B와 패턴을 한 줄씩 입력한다. `2`를 선택하면 같은 폴더의 `data.json`을 읽어 일괄 분석한다. `3`을 선택하면 보너스 패턴 생성기를 실행한다.

## 구현 요약

- `mac_score`는 2차원 배열의 같은 위치 값을 곱한 뒤 모두 더하는 MAC 연산을 이중 반복문으로 수행한다.
- `normalize_label`은 `+`와 `cross`를 `Cross`로, `x`를 `X`로 표준화하고 `normalize_filter_key`도 같은 정책을 사용한다.
- `get_filter`는 `filters.size_N`의 키를 정규화해 `cross`, `Cross`, `+` 같은 표기를 내부 라벨로 매핑한다.
- 점수 차이의 절댓값이 `1e-9`보다 작으면 동점으로 보고 `UNDECIDED`를 반환한다.
- JSON 케이스의 키에서 `size_N`을 추출하고, 해당 크기의 필터를 선택한다.
- 크기·행·열·숫자·라벨을 케이스 단위로 검증하여 오류가 전체 프로그램 중단으로 이어지지 않게 한다.
- 성능 측정은 파일 I/O와 출력 시간을 제외하고 MAC 함수 호출 구간을 10회 반복한다.
- 보너스 기능으로 3 이상의 홀수 N을 입력하면 Cross 또는 X 형태의 N×N 이진 패턴을 자동 생성한다.
- 생성된 패턴은 콘솔에 출력되고 자기 자신과의 MAC 점수도 계산되어 생성 결과를 확인할 수 있다.
- 모드 1은 내부 판정 `Cross/X/UNDECIDED`를 사용자 화면에서 `A/B/판정 불가`로 표시하고, 모드 2는 과제 데이터 규칙에 맞춰 `Cross/X/UNDECIDED`를 유지한다.
- 모드 2 결과 요약에는 `UNDECIDED 수`와 실패 원인 분류가 표시된다.

## 결과 리포트

이 구현의 정상 데이터는 5×5, 13×13, 25×25 Cross 패턴을 사용하므로 각 케이스의 Cross 점수가 X 점수보다 높아 PASS가 된다.
`expected`의 `+`를 내부 표준 라벨 `Cross`로 변환하므로 데이터 표기와 판정 표기의 차이가 실패 원인이 되지 않는다.
`filter 키`의 `cross`와 `x`도 같은 표준 라벨 체계로 해석할 수 있도록 명시적으로 매핑한다.
부동소수점 입력에서는 사람이 기대한 동일 점수가 아주 작은 오차로 달라질 수 있다.
따라서 절대 오차가 `1e-9` 미만이면 동점으로 처리하여 경계값의 잘못된 승패를 줄인다.
동점은 임의의 클래스를 고르지 않고 `UNDECIDED`로 출력한다.
케이스 키, 필터 크기, 패턴 크기, 라벨이 잘못되면 해당 케이스만 FAIL로 기록한다.
이때 실패 사유를 데이터/스키마 문제로 남기므로 MAC 로직 오류와 구분할 수 있다.
정상 케이스의 판정이 expected와 다르면 로직 또는 데이터 의미가 어긋난 것으로 보고 판정 불일치를 기록한다.
MAC는 N×N 위치를 한 번씩 방문하므로 한 번의 점수 계산에 N²회의 곱셈·누적이 필요하다.
따라서 입력 크기가 N에서 2N으로 증가하면 연산 횟수는 대략 4배가 되어 시간 복잡도는 O(N²)이다.
성능 표의 `연산 횟수(N²)`와 평균 시간(ms)을 함께 비교하면 이 증가 경향을 확인할 수 있다.
실제 시간은 실행 컴퓨터와 Python 상태에 따라 달라지므로 평균 시간은 실행 시 측정된 값이 기준이다.

## 라벨 추가 및 실패 진단 절차

새 라벨을 추가할 때는 다음 순서를 지킨다.

1. `normalize_label`에 입력 표기와 표준 라벨 매핑을 추가한다.
2. 필터 키는 `normalize_filter_key`와 `get_filter`를 통해 같은 표준 라벨로 찾게 한다.
3. `classify_scores`의 판정 결과와 모드별 출력 문자열을 확인한다.
4. expected 라벨, 필터 키, 정상 판정, 동점 판정을 각각 포함한 테스트 케이스를 추가한다.
5. JSON 전체 분석과 사용자 입력 모드를 다시 실행해 PASS/FAIL 및 출력 표기를 확인한다.

실패 원인은 데이터/스키마 문제(키·크기·라벨·배열 구조), 로직 문제(잘못된 필터 선택 또는 판정), 수치 비교 문제(epsilon 경계)로 분리한다. 모드 2는 실패 케이스를 중단하지 않고 목록과 원인별 건수로 보고한다.

## 대형 패턴과 CPU/NPU 병목 분석

1000×1000 패턴은 배열 하나만 해도 1,000,000개 값을 보관하며, 패턴·필터를 함께 사용하면 메모리와 캐시 접근량이 빠르게 증가한다.
현재 직접 구현은 모든 위치를 순서대로 방문하므로 한 번의 MAC에 N²회의 곱셈과 누적이 필요하고, N=1000이면 약 1,000,000회 위치 연산이다.
우선적인 최적화는 입력 크기·메모리 사용량 검증, 불필요한 복사 제거, 연속 메모리 접근, 반복 측정 안정화 순서로 진행한다.
그 다음에야 1차원 배열 변환, 블록 처리, 멀티프로세싱 또는 전용 하드웨어를 검토한다.
현재 구현은 학습용 CPU 직렬 반복문이므로 한 시점에 소수의 명령만 처리하고, N이 커질수록 반복 횟수와 메모리 접근이 병목이 된다.
NPU는 수많은 MAC을 병렬로 처리해 같은 패턴의 처리량을 높이지만, 데이터 이동과 메모리 대역폭이 병렬 연산 자체보다 병목이 될 수 있다.
따라서 대규모 처리에서는 연산 유닛 활용률뿐 아니라 메모리 전송량, 캐시 적중률, 데이터 재사용을 함께 측정해야 한다.
이 프로젝트는 외부 라이브러리 없이 원리를 확인하는 과제이므로 실제 NPU 최적화는 제안 사항이며, 구현·검증된 기능과 구분한다.

## epsilon 선택 근거

`EPSILON=1e-9`는 과제 권장 기준을 그대로 사용한 값이다. 정수 0/1 패턴에서는 MAC 결과가 정수가 되어 동점 판정이 안정적이고, 실수 입력에서는 1e-9보다 작은 반올림 차이를 승패로 확대하지 않는다. 실제 데이터 범위가 달라지면 절대오차와 상대오차 민감도 테스트를 추가한 뒤 값을 조정한다.

## 과제 목표별 답변

| 과제 목표 | 답변 |
|---|---|
| MAC이 무엇이며 AI에서 왜 중요한가? | MAC은 같은 위치의 값을 Multiply한 뒤 Accumulate하는 연산이다. 합성곱과 신경망의 유사도 계산에서 반복적으로 사용되므로 AI 칩이 병렬 처리하는 핵심 연산이다. |
| 입력 패턴과 필터의 유사도는 어떻게 계산하는가? | 패턴과 필터를 같은 크기로 겹친 뒤 각 위치의 값을 곱하고 모든 곱을 더한다. 점수가 높을수록 해당 필터와 더 유사하다고 본다. |
| data.json 라벨을 왜 표준화하는가? | `+`, `cross`, `x`처럼 데이터에 여러 표기가 있을 수 있기 때문이다. 프로그램 내부에서 `Cross`, `X`로 통일하면 비교 조건이 단순해지고 라벨 표기 차이로 인한 오판정을 막을 수 있다. |
| 부동소수점 오차와 epsilon은 무엇인가? | 실수 계산은 아주 작은 반올림 오차가 생길 수 있다. `abs(score_a-score_b) < 1e-9`를 동점으로 보는 epsilon 정책으로 거의 같은 점수를 잘못된 승패로 판정하지 않는다. |
| 크기 증가에 따른 시간 복잡도는? | N×N 배열의 모든 위치를 방문하므로 MAC 연산 횟수는 N²이고 시간 복잡도는 O(N²)이다. 표에는 실제 평균 시간과 N²를 함께 출력한다. |
| 실패 케이스를 어떻게 진단하는가? | 키·라벨·배열 구조·크기 문제는 데이터/스키마 문제로, expected와 실제 판정 불일치는 로직 또는 데이터 의미 문제로, 거의 같은 실수 점수의 승패 문제는 수치 비교 문제로 분리한다. |

## 재현성 및 검증 상태

- 구현 완료: `main.py`, `data.json`, `README.md`, Cross/X 패턴 자동 생성 보너스
- 모드 1: 3×3 입력 검증, MAC 점수, 판정, 성능 표 제공
- 모드 2: 5×5·13×13·25×25 JSON 분석, PASS/FAIL, 요약, 성능 표 제공
- 자동 검증: JSON 파싱, 컴파일, 모드 2 실행, 모드 1 정상 입력, 필터 키 정규화, 동점 문자열, 보너스 패턴 생성을 확인한다.
- 보너스 검증: N=5 Cross와 N=3 X 자동 생성 결과 및 자기 MAC 점수를 확인한다.
- 사람 확인 필요: 콘솔에서 직접 잘못된 행/열 입력을 넣었을 때 재입력 안내가 읽기 쉬운지 확인한다.
